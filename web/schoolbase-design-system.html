SchoolBase

A data-workspace UI for the School Management platform — records, attendance, grading, exams and archiving presented as filterable, groupable tables. Built for staff who live in the data, not a marketing site.

02

Typography

Inter everywhere — a neutral, highly legible workhorse. No display serif; the interface should read as software. Numbers use tabular figures so columns of grades and percentages line up.

Rows are dense

Default row height 34px (Short). Options: Medium 48, Tall 64, Extra-tall 88 — same as Airtable’s row-height control.

Radius stays small

3–6px on cells, chips and buttons; 8–12px on panels, popovers and records. No pill-shaped buttons.

Shadows are for layers

Flat grid; soft shadows only on things that float — popovers, the expanded record, toasts. Everything else uses 1px borders.

07

Redesign prompt · UI UX Pro Max

Paste into Claude Code / Cursor / Windsurf with the ui-ux-pro-max skill installed. It locks this Airtable-style system so the skill builds the workspace instead of choosing a new look.

prompt.txt 
Use the ui-ux-pro-max skill to redesign the frontend of my School Management
platform. This is an internal ADMIN tool, not a marketing site — model it closely
on Airtable: a data workspace of filterable, groupable tables, NOT a landing page.

Product type: B2B admin dashboard / data workspace (school records system)
over a Java/Spring REST API, JWT auth, roles ADMIN / TEACHER / STUDENT.
Style intent: Airtable-like spreadsheet–database UI (data-dense, utilitarian).
Stack: React + Tailwind + TanStack Table (virtualized rows) + shadcn/ui for
popovers/menus.  (swap for Vue/Nuxt or Laravel+Livewire if preferred.)

Lock this design system — do NOT re-pick a style:
• Chrome is neutral; the DATA carries the color.
• Colors: primary/action + selection blue #2D7FF9 (hover #166EE1);
          per-base accent bar #0F7B7B; canvas #F7F7F8; surface #FFFFFF;
          hover #F2F2F4; border #E5E5E7; grid line #E2E2E4;
          text #1D1F25; secondary #616670.
• Select-field palette (light bg / dark text; status = tag + label, never color alone):
          green #D1F7C4/#338A17 · red #FFDCE5/#D91F44 · orange #FEE2D5/#C8461F ·
          blue #CFDFFF/#2750AE · yellow #FFEAB6/#B87503 · purple #EDE2FE/#6B46C1 ·
          teal #C2F5E9/#0A8F88 · cyan #D0F0FD/#0B76B7 · gray #EEE/#585B62.
          Map: Present=green, Absent/Flagged=red, Late=orange, Excused=blue,
          At-risk=yellow, Distinction=purple, Archived=gray, Admin=purple,
          Teacher=teal, Student=blue.
• Type: Inter only, no serif. 13px grid cells / 14px UI; tabular-nums for
          numbers; 34px default row height (Short/Medium/Tall/Extra-tall options).
• Radius small: 3–6px on cells/chips/buttons, 8–12px on panels/popovers/records.
          Flat grid; soft shadows only on floating layers.

Signature = the record grid. Every table has: colored base bar + table tabs;
a toolbar (view switcher · Hide fields · Filter · Group · Sort · Color · Row height ·
Share · search); typed fields with a field-type icon in each column header
(text, number, percent, single/multi select, date, checkbox, collaborator,
linked record, attachment, formula); colored select chips; sticky header + first
column; row-hover reveals checkbox + expand; 2px blue active-cell ring; group
headers with live counts; “Add record” pinned bottom; “+” add-field column.
Views: Grid, Kanban, Calendar, Gallery, Form. Expanded record = a side sheet of
the fields as an editable form.

Screens (map to API), each with loading / empty / error via shared ApiError
(400 validation · 404 · 409 conflict · 401/403):
1. App shell — base bar + table tabs + left views sidebar.
2. Students / Teachers tables — roster grids, expand to record.
3. Courses & Promotions — linked-record fields (course↔teacher, student↔promotion).
4. Sessions — grid + a signing-window record (open / close / cancel, countdown,
   signed N/total); closing marks non-signers Absent.
5. Attendance — per-session grid, student self-sign, justify → Excused.
6. Grades — editable number cells (0–20), averages, promotion rankings (sort view,
   rank-1 = purple Distinction chip).
7. Exams — attempts grid, proctoring-event log, integrity-threshold meter,
   “Flagged” filtered view for review.
8. Reporting — at-risk view = a saved filter (attendance < 75% AND average < 10),
   grouped by promotion.
9. Archive — read-only grid; archived rows are dimmed and reject edits.

Anti-patterns to AVOID: marketing hero / big headline, serif display fonts,
gold/terracotta editorial accents, dashboard indigo-purple gradients, pill-shaped
buttons, heavy drop shadows, color-only status, emoji icons (use SVG:
Phosphor/Lucide), sparse low-density layouts. Keep it dense, gridded, functional.

Quality floor: WCAG AA contrast, visible keyboard focus, full keyboard grid
nav (arrows between cells, Enter to expand), prefers-reduced-motion respected,
responsive 375/768/1024/1440 (grid → horizontal scroll on mobile, records stack).

First generate + persist the design system to design-system/MASTER.md, then build
the app shell + Students grid, and show me that before continuing.
